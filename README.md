# Fragment releases

This repository is the official catalog of **community plugins for Fragment**. Fragment's *Community plugins* tab (Settings ▸ Community plugins ▸ Browse) reads its list of plugins directly from this repository.

| File | Purpose |
| --- | --- |
| [`community-plugins.json`](community-plugins.json) | The list of community plugins. |
| [`community-plugin-stats.json`](community-plugin-stats.json) | Download counts and last update dates, refreshed daily by a workflow. |
| [`community-plugins-removed.json`](community-plugins-removed.json) | Plugins that were removed from the catalog. |

## Community plugins

### Submit your plugin

Before submitting, make sure your plugin works and is ready to be used by others.

1. Start from the template: [RebornFlamme/fragment-sample-plugin](https://github.com/RebornFlamme/fragment-sample-plugin). Your repository must have, at the root of its default branch:
   - `README.md`: what the plugin does and how to use it;
   - `manifest.json`: the plugin manifest (`id`, `name`, `version`, `minAppVersion`, `description`, `author`…);
   - `LICENSE`.
2. Publish a GitHub release (see [Releases](#releases) below).
3. Fork this repository and add an entry for your plugin **at the end** of `community-plugins.json`:

   ```json
   {
     "id": "your-plugin-id",
     "name": "Your Plugin",
     "author": "Your Name",
     "description": "One sentence describing what your plugin does.",
     "repo": "your-github-user/your-repo"
   }
   ```

   - `id` must be unique, use only lowercase letters, digits and dashes, and be identical to the `id` of your `manifest.json`.
   - `repo` is the GitHub path of your repository (`owner/name`).
4. Open a pull request using the [plugin template](.github/PULL_REQUEST_TEMPLATE/plugin.md) (append `?template=plugin.md` to the pull request URL, or select it from the template list) and go through the checklist.

A workflow validates every pull request that touches `community-plugins.json`. For each **new** entry it checks that the repository exists, has `README.md` and `manifest.json`, that its latest release has `main.js` and `manifest.json` attached, and that the release's `manifest.json` has the same `id` and a `version` equal to the release tag. Fix any reported error and push again.

Once your pull request is merged, the plugin appears in Fragment's *Community plugins* tab.

### Releases

Fragment installs a plugin from the assets of a GitHub release of its repository:

```
https://github.com/<repo>/releases/download/<version>/main.js
https://github.com/<repo>/releases/download/<version>/manifest.json
https://github.com/<repo>/releases/download/<version>/styles.css   (optional)
```

- The release **tag must be exactly the plugin version**, as written in `manifest.json` (`1.0.0`, **not** `v1.0.0`).
- `main.js` and `manifest.json` (and `styles.css` if your plugin has one) must be attached to the release as **individual files**, not only inside the source archives.
- The `manifest.json` at the root of your default branch is the one Fragment reads to find the latest version: update it with each release.
- Optionally, add a `versions.json` at the root of your repository mapping each plugin version to the minimum Fragment version it needs (`{"1.0.0": "0.1.0"}`). Fragment then installs the most recent version compatible with the user's app.

To publish an update, bump `version` in `manifest.json` (and `versions.json`), then create a new release with that tag. You do not need to open a new pull request here.

### Stats

`community-plugin-stats.json` is recomputed every day by the [Update plugin stats](.github/workflows/update-stats.yml) workflow, from the GitHub releases of every plugin of the catalog:

```json
{
  "your-plugin-id": {
    "downloads": 1234,
    "updated": 1761091200000,
    "1.0.0": 1000,
    "1.0.1": 234
  }
}
```

- each version key is a release tag, with the download count of that release's `main.js`;
- `downloads` is the sum over all releases;
- `updated` is the publication date of the most recent release, in milliseconds since the Unix epoch (absent when the repository has no release yet).

Do not edit this file by hand.

### Removal

Plugins can be removed from the catalog, for instance when they are no longer maintained, break Fragment, or are found to be malicious. Removed plugins are listed in `community-plugins-removed.json` with their `id`, `name` and the `reason` of their removal:

```json
[
  {
    "id": "some-plugin",
    "name": "Some Plugin",
    "reason": "No longer maintained."
  }
]
```

If you are the author of a plugin and want it removed, open a pull request that removes its entry from `community-plugins.json` and adds it to `community-plugins-removed.json`.
